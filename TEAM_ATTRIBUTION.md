## Collaborative source authorship

The Go Reserve codebase was worked on by multiple team members and from multiple development machines. Because local Git configuration can record the identity configured on the laptop rather than the person currently typing, this portfolio does **not** use Git author metadata as the sole measure of contribution.

At the same time, this repository does not relabel every team-authored file as individually authored by the portfolio owner. The correct interpretation is:

- the **application and pipeline are team output**;
- the portfolio owner may present them as collaborative project experience;
- direct individual contribution proof is kept where it is available;
- original Git history remains the authoritative record of repository events.

## Why source is mirrored here

A collaborative project is still valid portfolio evidence. Recruiters often evaluate how candidates worked within a shared codebase, understood system boundaries, contributed to delivery, and can explain engineering decisions—not only whether every line was written by one person.

The files in this repository are therefore presented as **representative team engineering artifacts** with clear source links rather than as a claim of sole authorship.
